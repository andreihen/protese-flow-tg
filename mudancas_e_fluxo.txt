=============================================================================
             CADIFY - MUDANÇAS REALIZADAS E FLUXO DE SERVIÇOS
=============================================================================

Este documento resume as modificações técnicas aplicadas ao sistema Cadify
e detalha o fluxo de serviços integrado entre o backend (Django REST) e o
novo frontend SPA (React + Vite + TypeScript).

---

1. MUDANÇAS REALIZADAS NO SISTEMA
=============================================================================

1.1 Backend Django (API & Integração):
   * Ativação e configuração do Django REST Framework e CORS Headers para permitir
     comunicação segura com a aplicação rodando localmente (porta 5173).
   * Integração de Autenticação Baseada em JWT (JSON Web Tokens) usando simplejwt,
     com rotas dedicadas para obtenção de token (`api/token/`) e atualização (`api/token/refresh/`).
   * Adição do endpoint `@action upload_anexo` na `PedidoViewSet` (no arquivo api_views.py)
     para permitir que o frontend faça o envio individual de múltiplos arquivos STL/PLY 
     de forma associada ao pedido criado.
   * Criação e aplicação de migrações correspondentes a novos campos de data no modelo Pedido.

1.2 Frontend React + Vite + TypeScript:
   * Criação da estrutura SPA no diretório `frontend/` com compilação livre de erros TypeScript.
   * **index.css**: Implementação de um Design System responsivo no modo escuro (Dark Mode HSL)
     com visual contemporâneo baseado em Glassmorphism.
   * **api.ts**: Cliente Axios com interceptores inteligentes que adicionam automaticamente
     o cabeçalho 'Authorization: Bearer <token>' e renovam a sessão via refresh token na 
     ocorrência de erros 401.
   * **AuthContext.tsx**: Contexto unificado que gerencia login, logout e persistência do usuário.
   * **Layout.tsx**: Componente de Layout contendo uma Sidebar responsiva cujas opções de menu
     são renderizadas condicionalmente de acordo com a função do usuário logado (Dentista vs Cadista vs Gestor).
   * **Telas Criadas (Views)**:
     * *Login.tsx*: Interface estilizada para entrada segura de credenciais.
     * *Dashboard.tsx*: Exibe cards com KPIs dinâmicos e uma tabela avançada com pesquisa,
       ordenação e filtros de status.
     * *NovoPedido.tsx*: Painel interativo com Odontograma Visual completo onde o dentista
       seleciona dentes específicos (11 a 48) e anexa múltiplos arquivos STL.
     * *DetalhesPedido.tsx*: Visualiza os dados clínicos, exibe a linha do tempo (stepper)
       do pedido, oferece downloads dos anexos e botões de ação contextuais.

2. FLUXO ATUAL DE SERVIÇOS (PASSO A PASSO INTEGRADO)
=============================================================================

A interação entre o Dentista, a equipe de laboratório (Cadista) e o sistema segue o
seguinte fluxo operacional automatizado através da API REST:

2.1 Autenticação:
   * O usuário insere suas credenciais na tela do frontend (`/login`).
   * O frontend dispara um POST para a API do backend (`/api/token/`).
   * A resposta retorna o token de acesso (curto prazo) e de atualização (longo prazo).
   * O frontend salva os tokens e busca os detalhes do perfil do usuário em `/api/usuarios/`.

2.2 Criação e Upload de Próteses (Dentista):
   * O Dentista clica em "Novo Pedido" e preenche os dados (Paciente, Serviço, Cor, Prazo).
   * No **Odontograma**, seleciona os dentes clicando nas representações gráficas.
   * Insere os arquivos de escaneamento 3D (STL/PLY).
   * Ao clicar em enviar:
     1. O frontend envia os dados textuais e a lista de dentes selecionados via JSON para `/api/pedidos/`.
     2. O backend processa, cria o registro e devolve o ID do Pedido gerado.
     3. O frontend então faz múltiplos envios sequenciais (POSTs) contendo os arquivos para o endpoint
        `/api/pedidos/{id}/upload_anexo/` usando codificação multipart/form-data.
     4. O caso inicia automaticamente com o status "Aguardando Início" (PENDENTE).

2.3 Fila de Produção (Cadista):
   * O Cadista acessa o painel e visualiza na tabela os casos pendentes.
   * Clica em "Ver Caso" e depois em "Iniciar Produção".
   * A API executa o endpoint `/iniciar_producao/`, vinculando o ID do Cadista ao Pedido
     e mudando o status para "Em Produção" (EM_PRODUCAO).

2.4 Finalização e Desenho 3D (Cadista):
   * Após projetar a prótese no software de CAD, o Cadista retorna à tela de Detalhes.
   * O sistema exibe um campo de upload específico para o desenho finalizado.
   * O Cadista envia o arquivo entregável. A API registra o modelo e muda o status para "Concluído" (CONCLUIDO).

2.5 Revisão e Aprovação (Dentista):
   * O Dentista visualiza na tabela que o caso está concluído.
   * Acessa a tela de detalhes, onde o link de download do projeto final do Cadista está disponível.
   * O Dentista pode:
     * Clicar em "Aprovar Caso": O status muda para "Aprovado" (APROVADO), finalizando o ciclo de serviço.
     * Clicar em "Solicitar Ajuste": Abre-se um campo onde ele descreve o erro anatômico ou estético.
       O status vira "Ajuste Solicitado" (RETRABALHO) e o caso volta imediatamente para a fila do Cadista.

3. COMO EXECUTAR OS SERVIÇOS LOCALMENTE
=============================================================================

Para subir os servidores em sua máquina de forma rápida e testar a aplicação:

3.1 Iniciar a API Backend (Django):
   * Abra um terminal no diretório raiz do projeto e execute:
     `.\venv\Scripts\python src\manage.py runserver`
   * A API estará respondendo em `http://127.0.0.1:8000/`.

3.2 Iniciar o Frontend SPA (React + Vite):
   * Abra outro terminal na pasta `frontend` e execute:
     `npm run dev`
   * A tela de login abrirá no navegador no endereço: `http://localhost:5173/`.

3.3 Contas de Teste Integradas:
   * **Dentista**: Usuário: `dentista` | Senha: `Password123`
   * **Administrador/Gestor**: Usuário: `admin` | Senha: `Password123`
